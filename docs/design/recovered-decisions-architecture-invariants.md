(ten laws, frozen) and `CLAUDE.md`'s "Non-negotiable laws (short form)" (seven). The short form is
what every agent reads; the Spine is what is frozen. See **C-01**.*

## §2 THE KERNEL CONTRACT — INVARIANTS MADE MECHANICAL

surface requires a director-approved ADR to change (`docs/m0-kernel-spec.md:118`).*

| Decision | Source (file:line) | Status | Implication for future architecture |

| **A-15 — STATE IS PLAIN DATA TABLES, EACH OWNED BY EXACTLY ONE SYSTEM; READ/WRITE ENFORCED BY CONSTRUCTION.** *"`WorldState` is plain data: a set of tables … each owned by exactly one system … The kernel constructs each system's `SimContext` with typed writable handles to its owned tables only. **An agent cannot silently write another system's state — the reference does not exist.**"* | `docs/m0-kernel-spec.md:54-64` (§3.1, frozen); Spine `docs/civ-sim-architecture-v3-outline.md:31` | RATIFIED | Ownership is a compile-time fact, not a convention. ### §4a THE REJECTED UNIVERSAL `CapabilitySystem` — THE FULL REJECTION RECORD

*Recorded at the mandate's explicit instruction, with the precise reason and the revisit
conditions. Three separate records participate; none of them is reconciled here.*

**WHAT WAS PROPOSED.** A prior agent's architecture pass proposed a capability *seam* shaped

as such by D-042 at `docs/d042-empire-and-player-control-addendum.md:278-279`. [INFERRED that this
is the proposal D-042 §7.3 answers: D-042 §14.5 names that document and section by name, and the
note is headed *"Note against a prior audit recommendation of mine"* (`:276`).]

**THE PRECISE REASON FOR REJECTION — it is Law 6, not taste.** §7.3 sits *inside* §7, whose title is
**"STATE-MEDIATED DEPENDENCY (reaffirms Law 6)"** (`:134`), and whose two preceding clauses are its
premises: *"Systems communicate through World State and kernel contracts, **never by calling sibling
domain systems**"* (`:136-138`) and *"Economy may depend *conceptually* on knowledge, government,
military, transport and institutions — **that never justifies a sibling call**"* (`:139-140`). The
rejected object is named twice and both times by the same property: a system *"that **owns every
capability or coordinates every domain**"* (`:141-142`), listed as *"a universal `CapabilitySystem`
**God object**"* (`:200`). [RATIFIED] **The rejected property is therefore CROSS-DOMAIN COORDINATION
AND OWNERSHIP, not capability evaluation as such** — §8.1, in the very next section, ratifies that
capability evaluation continues, on the D-020 machinery (**A-50**).

**WHAT IS PERMITTED IN ITS PLACE, stated by the same record.** *"The seam is conformant **only** as a

has — and **not** as a coordinating owner."* (`:280-282`, §14.5). [RATIFIED] A second, independent
statement of the same fence sits in the sibling rejection **A-43**: what binds domains together is a
**stable identity/key**, not a container (`:60-65`). [RATIFIED]

**BLAST RADIUS OF THE REJECTION.** It reaches every future domain that wants to ask "can this
civilization do X yet?" — knowledge, technology, institutions, government, military, economy. Each
must evaluate its own predicates against published variables inside its own system, accepting the
one-turn lag (**A-18**), rather than consulting a central authority. [INFERRED from A-41 + A-42
