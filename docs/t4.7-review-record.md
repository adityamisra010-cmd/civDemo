## 2. THE ARCHITECTURE AS BUILT

```
span     = min(1, riverCells / stride)
nodeCost = (1 − span) · blockMeanCost + span · riverCostFactor
```

A coefficient **inside** `TraversalLattice.Build`'s per-block cost aggregation (law 2) — not a
free-floating modifier. Rivers do **not** change passability (river cells are LAND; that was proven
structurally at T4.9). `riverCells == 0` takes the untouched `costSum / cells` in the same expression
and the same order as before T4.7, so **a river-free world is bit-identical** to the pre-T4.7 lattice
— which is why the toy golden is a control and must not move.

Honoured, all verified in the diff: no second river graph · no `NetworkEdge` promotion · no stride
change · **no persisted river routing state, no new table, no schema bump** (`TerrainSet` remains the
authoritative geometry, ADR-008) · vessels/ports/naval out of scope.

`transport.riverCostFactor = 0.20`, TUNE, with its derivation stated in `sim.json`: reference class
**declared before any number was computed** — pre-modern freight ratios (Diocletian's Price Edict,
corroborated by medieval English cartage-vs-river) put road : river per ton-km at ~5–10 : 1, giving
the ratified band r ∈ [0.10, 0.20]. **0.20 is the CONSERVATIVE edge** — the weakest river advantage
the class supports — chosen because it is also the edge carrying a *measured* outcome (T3.6b's
pixel counterfactual: 4/27 ore-pair crossings at r = 0.20 against 0/27 river-blind). Taking the
strong edge would have manufactured a larger effect from the same evidence. Range-validated in
`Build` to (0,1].

## 6.1 THE METRIC IS NON-LINEAR — "98.4 %" IS A 42.4 % SHED

`MigrationConcentrationTests.Profile()` computes `frac = outflow / pop` where `pop` is summed
**AFTER** the step (`MigrationConcentrationTests.cs:63-71`) — i.e. the denominator is the population
*remaining*, not the population *before*. So `reported = true/(1−true)`:

| reported | true shed of pre-migration population |
| --- | --- |
| 0.984 | **0.4960** |
| 0.200 (the guard) | 0.1667 |
| 0.061 (post-correction baseline) | 0.0575 |

The measure diverges as the true shed approaches 0.5 and **exceeds 1.0 above it**. The headline
number therefore overstates the physical event by roughly 2×. This is a pre-existing property of the
rig, unchanged by T4.7, and the guard was calibrated in the same units — but it must be stated,
because "98.4 % of a settlement left" is not what happened.

## 6.3 FAMINE FLIGHT IS NOT INVOLVED — the hypothesis is REFUTED

**`deficit = 0.0000` at every one of the four events.** Famine flight enters the driver as
`FamineFlightFactor × deficit_src`, so at deficit 0 that term is **exactly zero**. The one channel
that is *deliberately not* gap-capped (D-021's Exit valve, "a surge by design, bounded by the
overdraw scaler alone") **contributed nothing**. The prior working hypothesis — "the river cost opens
a gap the T2.8 architecture cannot bound, via famine" — is refuted by measurement.

Arable is also **bit-unchanged across each event** (9099.1 → 9099.1 etc.), so no catchment
re-partition occurs *during* the shed.

## 6.4 THE T2.8 CAP HOLDS — it is not bypassed, and it never promised what was assumed

With `deficit = 0` the entire flow is the **gap channel**, which IS capped:
`gapScale = min(1, cap/gapDesire)`, `cap = GapClosingFraction × m*`, `f = 0.25`.

The cap's guarantee (`MigrationSystem.cs` header) is that **overshoot is structurally impossible** —
at `f < 1` the post-move gap keeps its sign. **It does not bound the absolute fraction of a
settlement that may move in one turn.** `m*` is the flow that would *equalise* per-capita
attractiveness, so when the per-capita gap is large, `0.25 × m*` is itself a large fraction of the
source population. A 42.4 % move is the cap **working as specified**, not failing.

**MIGRATION CAP: HOLDS.** No invariant is violated; conservation is untouched (people move by
`Ledger.Transfer`, world totals invariant).
