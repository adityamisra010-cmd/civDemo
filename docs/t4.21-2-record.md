## 8. Deviations from the spec text, stated

1. **Source-basin outflow is the DEST-SCALED outflow** (`Σ_j gapScale_ij × destScale_j × gapDesire_ij`),
   i.e. the scale chain is sequential (pair → destination basin → source basin → vacancy → overdraw as
   the spec pins the ORDER); the spec's `outflow_i` is not written out. A source already held back by its
   destinations' basins is not limited twice for the same people. `M_Basin_FanOut_…` has single-source
   destinations (destScale 1.0), so it reads the same under either form.
2. **`M_VacantViableDestination_AcceptsUpToCap` second turn**: the spec's clause "a second turn accepts more
   (labour grew)" needs Production; in the migration-only rig N_lim is HELD and the second turn accepts
   what the shrunken vacancy allows (V = 80 − 45 = 35 ⇒ cap 17.5 ⇒ 17), which is what is asserted.
3. **Flight weight association**: `flight = φ_b × count_b × (w_ij × vacScale_j)` (the vacancy factor
   folded into the pair weight, multiplied only when < 1) rather than `φ × count × w × vac`; no pinned
   number depends on the association and the test expectations multiply the plan's own factors.
4. **"Green" now means ONE inherited red**: `Dev_MalthusCorridors_AllInBand(seed 42)` passes on this tree
   (no starvation deaths in the dev horizon under bounded migration); the ruling's quarantine is
   untouched. Reported, not acted on.
