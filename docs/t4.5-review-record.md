# T4.5 — NON-STATE PEOPLES (D-037 B3) — REVIEW RECORD

Branch `t4.5-non-state-peoples`, cut from `origin/main` `ba96b1c`. NOT MERGED, NOT SELF-CERTIFIED.

## 1. WHAT WAS BUILT — THREE MECHANISMS, NO NEW STATE

**1. The carrier is the absence of a `ControlRow`**, exactly as authorized. `ControlRow`'s own
contract already admits "exactly one state control row, OR none". No `StatelessSettlement` table,
no new population carrier, no new polity type, **no schema bump** (verified in §5).

**2. Subsistence is the existing `Herding` sector** through the existing `FromDeposits()` pathway.
No parallel herding model was written.

**3. The drought coupling — the actual implementation gap — is closed.** `Farm()` already consumed
`HarvestWeatherRow.Multiplier`; `FromDeposits()` did not. Weather is now passed by the CALLER:
the Herding call passes `HarvestWeatherFor(prev, settlement)`, the EXTRACTION call passes `1.0`.

The semantic location was traced rather than bolted on: weather multiplies `ratePerYear` in the
same position and order as `Farm` does it — once, before dt integration and before the D-004
remainder is added. Extraction's `× 1.0` is exact in IEEE-754, so its output is bit-identical.
Farm's inline weather lookup became the shared `HarvestWeatherFor` helper, extracted verbatim
(same scan order, same first-match break, same absent-row-is-1.0 default) so farming and herding
cannot drift onto two readings of one signal.

**4. Appropriation** (`AppropriationSystem`, `SystemId` 16, pipeline slot between `production` and
`consumption`) — a hungry non-state people takes grain. It owns **no tables** and publishes none.

- **No second definition of hunger.** The trigger is `ConsumptionSystem`'s existing
  `ConsumptionDeficitRow`, read from PREV like every other cross-system signal.
- **No new constant.** The amount is the raider's own measured shortfall,
  `DeficitRatio × DemandUnits`, both already on the row. No raid size, no greed factor, no
  threshold, no timer, no cooldown, no RNG.
- **No ledger reason was added.** `Ledger.Transfer` "conserves by construction (no flow entry)"
  and takes no `ReasonId`. An `Appropriation` reason was drafted and then REVERTED as dead code —
  the tree's own precedent is explicit: "band aging moves people BETWEEN stocks via
  Ledger.Transfer, which conserves by construction and records no source/sink row."
- **`ClampToAvailable`**, so a victim can be emptied but never overdrawn.
- **Victim** = the other settlement holding the most grain, tie-broken to the LOWEST id by a
  strictly-greater ascending scan — the (stock desc, id asc) composite key, on longs, no
  floating-point comparison.

## 2. ONE IMPLEMENTATION DECISION THAT NARROWED THE AUTHORIZED TRIGGER — STATED PLAINLY

The authorized design says the discriminator is the absence of a `ControlRow`. **Implemented
literally, that made every settlement in the world a raider**, because nothing in `Sim.Core`
writes `Controls` — T4.3 shipped claim/control/recognition as schema only, and there is no
`Polities` table at all. So "stateless" is currently universal.

**This was not a theoretical worry; it was measured.** With statelessness as the sole condition,
the full suite showed `CollapseStabilityTests.CollapsingWorld_DeadStaysDead_NoResurrectionCycle`
failing with *"no settlement died food-less in the collapsing world — the resurrection detector is
vacuous again"*. Hungry villages were taking their neighbours' grain and surviving, which emptied
the precondition of an ADR-012 resurrection guard. That is world-wide famine relief, not steppe
raiding.

**The fix, and why it is inside the authorized design rather than a change to it:** the raider must
also be **HERDING-DOMINANT** — its largest sector is Herding. This is D-037 B3's actual subject
("Pastoralists, hunter-gatherers …") and the authorized design's own words ("A herding-dominant
stateless settlement therefore already has an existing production pathway"). It introduces no new
mechanism (`Sectors.Raw` exists), no new constant (largest-sector is a comparison, not a
threshold), no schema, and no scope expansion. Dominance is STRICT: an even plough/herd split is a
mixed village, not a herding people, and is pinned as such.

With the condition in place the collapse guard passes again.

**RECORDED FOR THE DIRECTOR TO OVERRULE IF THEY DISAGREE:** this narrows an explicitly authorized
trigger. It is the one design-adjacent judgement in the packet.

## 3. THE CONSEQUENCE THAT MATTERS — THE RAID IS DORMANT IN LIVE WORLDS

`Sectors.Default` is `Farming 0.55, Herding 0.15, Extraction 0.10, Crafting 0.12, Construction
0.08` — farming-dominant. **Measured over all 300 turns of the canonical founded world (seed 42):
ZERO herding-dominant settlement-turns**, so appropriation never fires there.

The mechanism ships complete and fully tested, but **it cannot fire in a live world until worldgen
places pastoralists**. D-037 B3 says non-state peoples are "M4 worldgen, present from turn zero —
NOT spawned". Placing them is worldgen work this packet's authorized design did not cover (it
forbids schema changes and never mentions worldgen), so it was NOT done here and is queued in
`docs/queue.md`. **Stated rather than left to look like a live feature.**

## 4. TESTS — 17 targeted, all passing

| area | coverage |
|---|---|
| **A carrier** | a world with no `ControlRow` is valid; population stays put |
| **B herding** | output comes through the existing `FromDeposits` pathway |
| **C drought** | herding scales linearly with the multiplier (1.0 / 0.5 / 0.25); **extraction does NOT** (ore is not a crop); **farming is unchanged** (refactor regression guard); absent row = 1.0 |
| **D deficit** | the full pipeline generates the hunger itself — no hand-set deficit |
| **E raid** | takes exactly the shortfall; Ledger-exact; **world grain conserved**; victim clamps at zero, never negative; deterministic and bit-exact on repeat; tie goes to the lowest id |
| **F boundary** | a CONTROLLED settlement in identical hunger does NOT raid, and removing the row restores it — the paired test proves the discriminator; an all-farming stateless village does not raid; an even split is not dominant |
| **G resistance** | scope fence as a test: no combat vocabulary and no RNG in the system's source |

Two test-design corrections worth recording, because both were real model findings:

- **A pure-pastoralist settlement is ALWAYS in deficit, in every weather.** The consumption basket
  is grain-dominant and a non-staple surplus substitutes INTO the staple but never the reverse, so
  a livestock-only settlement is short of grain regardless of the year and its deficit carries no
  drought signal at all. The end-to-end test therefore uses a MARGINAL MIXED settlement — which is
  also D-037 B3's "marginal terrain".
- **The mechanism is self-correcting and therefore phase-dependent**: hunger in turn *t* drives a
  raid in *t+1*, which feeds them, so *t+2* needs no raid. Assertions total over a window rather
  than sampling one turn, which would read a trough half the time.
