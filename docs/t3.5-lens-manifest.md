# T3.5 — required-lens manifest

Written **before** implementation, per ADR-015 §7.3 (standing practice on every
adversarial-mandatory packet). At handback each row is reconciled by name against the lenses that
actually **RETURNED RESULTS** — never against the launch call. **A missing lens is BLOCKING.**

T3.5 binds three needs and replaces the aggregation form for all of them. It is the first packet
to implement `docs/d035-needs-aggregation.md`, and the first where an *invented modifier* is a
live temptation on every coupling — hence a lens dedicated to the carrier test.

## Mutation testing — bounds stated before the sweep (ADR-015 §7.1)

- Clean-suite baseline measured immediately before the sweep and recorded.
- Per-mutant bound **5× the filtered-subset baseline**, hard timeout, killed at the bound.
- A mutant exceeding the bound is recorded `hangs; non-termination under this mutation`.
- One worktree per verifying agent, never shared (ADR-015 §6).

## Guard-test discipline (ADR-015 §7.4)

Every guard ships with a test **proven red** by removing the guard. Specifically: the D-035-B
mandatory test must fail against a weighted sum, and the inertness gate must fail if an unbound
need is given any effect at all.

## Vacuity discipline (ADR-015 §7.5)

Satisfactions are bounded in [0,1] and grievance has a floor. No assertion compares two values
resting against those bounds — assert strictly inside before comparing.

## Harness caution (ADR-015 §7.9)

The T3.4b review lost all six lenses to a broken subagent environment, and the error misdirected
the diagnosis for two runs. Before trusting any lens result here: confirm each agent reports a
pinned HEAD it actually read, and read the agent TRANSCRIPTS — not just the journal — if anything
returns empty. A review that cannot execute is not a review that found nothing.
