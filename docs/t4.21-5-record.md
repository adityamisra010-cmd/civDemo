## 1. THE ONE RULE THIS PACKET LIVES OR DIES BY

`docs/observability-architecture.md` §0 permits five field kinds and no sixth. The sixth kind — an
observer-side formula that happens to agree with the simulation today — is the failure this packet
exists to avoid, because a forensic layer that drifts is worse than none: it reports the drift as a
finding about the world.

So every field added here is exactly one of:

* **READ** — a value copied out of a row of `prev` or `next`, named with the world it came from;
* **RECOMPUTED** — a call to a PUBLIC static of the simulation, on the SAME state the simulation
  called it on (`FoodState.Of / DeficitRatio / EffectiveDeficit / IsAbandoned`,
  `FoodHeadroom.Limit / Vacancy / FeedableAtLimit`, `DemographicsSystem.Headroom`,
  `MigrationSystem.Plan / FlightFractionOf / FlightHazardScale`);
* **GAP** — a string that says what is missing and where it is computed and discarded, never a
  number.

`ExplainRecomputedFunctionTests.T421_EveryRecomputedField_IsTheStaticOnTheSameState_BitForBit`
is the assertion of that rule: 40 observed turns of the canonical founded world, every settlement,
every recomputed field, compared on `BitConverter.DoubleToInt64Bits` — so NaN equals NaN,
+infinity equals +infinity, and a second formula agreeing to fifteen digits still fails.

## 2. WHAT SHIPPED

### 2.1 Per-settlement telemetry (`SettlementRecord.cs`, `Observer.cs`, `TelemetryWriter.cs`)

Two sections APPENDED to `SettlementRecord`, so every existing field keeps its position:

* **`FoodStateSection`** — `prevRowsPresent`, `state`, `famineReason`, `nominalDeficit`,
  `effectiveDeficit`, `abandoned` (all RECOMPUTED on PREV); the applied `DisasterRow` block and the
  next-side **pending** block (READ, named as pending); `harvestWeatherApplied` (READ, permanent —
  the F1/G1 audit needs it); `foodLimit`, `vacancy`, `surplusRatio` (= `X/D`), `headroom`
  (RECOMPUTED).
* **`MigrationPlanSection`** — `exitOpenness`, `flightFractionPrime`, `flightBound`, `flightOut`,
  `gapOut`, `gapOutflowCap`, `srcScale`, `flightIn`, `gapIn`, `gapInflowCap`, `destScale`,
  `vacancyCap`, `desiredInflowAe`, `vacancyScale`, all INDEXED out of one `MigrationSystem.Plan`
  call per observed step, plus the `inflowAeByChannel` GAP string.

**Why PREV.** `FoodState.Of` on prev is the state IN FORCE for the step just observed: the deficit
the step read, the multiplier its harvest was multiplied by, the sector row its production obeyed.
A next-side classification would name the state of the step that has not run yet.

**Which dt.** `next.Clock.DtYears`. `TurnExecutor.Step` chooses `dtDays` at turn start, passes
`dtDays / YearDays` to every system, and stamps the clock with that same `dtDays` at the end — so
this is the dt the step integrated, not a second choice of dt. The bit-exact test would fail if it
were not.

**Founding records.** A settlement present in `next` and absent from `prev` was never planned:
`planRecorded` false and every planner reading `NaN`. *Not planned* is not *planned to zero*, and
the test asserts `NaN` rather than `0` for exactly that reason.

### 2.2 The schema tag — v3, and a reader that takes both

`TelemetryWriter.Schema` moved `telemetry/v2` → `telemetry/v3`: the writer's own documented rule is
that the tag moves with the field set, and this is a new field set.

`TelemetryRecordFile` now validates against `TelemetryWriter.ReadableSchemas` — an ENUMERATED
whitelist of exactly two vintages, not a relaxation. The justification is that v3 is v2 PLUS two
sections: no v2 key was renamed, moved or re-meant, so a v2 line is a v3 line with two sections
missing. A v2 line yields `TelemetryFoodState.Absent` / `TelemetryMigrationPlan.Absent`, whose
`Recorded` flag is FALSE — the reader says *the file does not say*, and never defaults a food state
into existence. A third tag is still refused, with the file and line named.

`ForensicSchema.Schema` stays `forensic/v1`, and the file now says why: the forensic run record
CARRIES the telemetry tag as a VALUE (`Schemas.Telemetry`, read straight off `TelemetryWriter`), and
a carried value moving is not that file's field set moving. Bumping it would tell a reader
something false.

### 2.3 Chronicle — the famine event is the simulation's famine

Before this packet the annals latched famine when the raw deficit crossed `famineOnsetDeficit = 0.15`
— the chronicle's OWN definition of famine, and precisely the conflation CR-015 forbids. Now:

| event | fires on |
| --- | --- |
| `FamineOnset` / `FamineEnd` | `FoodState.Of(world, s, simCfg) == Famine`, carrying the `FamineReason` ordinal as magnitude 2 so the prose binds `{reason}` from a RECORDED magnitude |
| `Disaster` (new) | the RISING EDGE of `FoodState.IsStruck` — one line per event, not one per turn |
| `FoodShortfallOnset` / `FoodShortfallEnd` (new) | the deficit crossing zero — the ordinary event the famine line used to usurp |

`famineOnsetDeficit` and `famineEndDeficit` are RETIRED from `ChronicleThresholds` and from
`chronicle.json`, along with the loader's hysteresis check that guarded them. The chronicle owns no
famine threshold any more, because famine is not a threshold. `ChronicleCollector` now takes
`SimConfig`; `UiSession` passes the one it already holds.

## 3. THE ONE SIMULATION-FILE EDIT, AND WHY IT IS NOT A MECHANISM CHANGE

`MigrationSystem.cs` gained ONE public static:

```csharp
public static double FlightHazardScale(MigrationConfig m) => m.BaseRatePerYear * m.FamineFlightFactor;
```

and `Plan`'s body now calls it instead of writing the product inline. The same two factors in the
same order: bit-identical by inspection, and the goldens confirm it (§5).

**This is a DEVIATION from spec §4's T4.21-5 file list, and it is deliberate.** Spec §3.11 requires
`flightFractionPrime` — φ at cohort profile 1 — which needs K. Writing `BaseRatePerYear *
FamineFlightFactor` in the observer would have been a SECOND implementation of that product: exactly
the sixth field kind §0 forbids, in the packet whose whole purpose is to forbid it. The choices were
(a) extract the static so there is one implementation, (b) copy the product, (c) declare the field a
GAP. (b) is barred by the contract. (c) would drop a field the spec's table names. (a) changes no
arithmetic and no mechanism. Recorded here for the director rather than left for a reviewer to find.

## 4. GAPS — what is NOT a number, and why

1. **`migrationPlan.inflowAeByChannel`.** `MigrationPlan.DesiredInflowAe` is ONE adult-equivalent
   figure over the gap AND flight channels together, because that is what the vacancy bound compares
   against; the planner forms no per-channel split. The observer therefore records none. The
   per-channel HEAD counts (`gapIn`, `flightIn`) ARE recorded. Splitting the adult-equivalent figure
   here would be an observer-side re-derivation of a quantity the simulation does not compute.
2. **Pairwise From→To flows, the damping matrix, the per-PAIR gap-closing scale.** Still not
   recorded; the ruled strings are verbatim. Per-destination CHANNEL totals now exist, which is what
   §3.11 asked for.
3. **`surplusRatio` with no demand row** is `NaN`, not 0: the ratio has no denominator. `foodLimit`
   on `FoodHeadroom`'s null arm is `+Infinity`, written as the string `"Infinity"`, so the null arm
   survives the round trip instead of being lost or read as a number.
4. **The applied disaster multiplier on a settlement with no `DisasterRow`** is a GAP with `NaN`,
   not `1.0`. The precedent is the weather and arable links, which also decline to print a system's
   default as if it were a reading.
5. **`recentStress` is NOT SHIPPED** — see §6.
