# T4.1d — TWO PATHS, ONE SEED: MANIFEST

**Written BEFORE the measurement (§7.13).** Isolating why the CLI replay path and T4.1's in-test
harness reported different artisan trajectories for the same seed with no orders.

**Why this outranks the split it was found under:** two instruments disagreeing about the same
world is the shape that hid a genuine migration reading for eleven nightly runs. If the
disagreement is in the WORLD rather than in the reporting, it is a **law 5 determinism** finding.

## PRE-COMMITTED READINGS (§7.15 — observable named, composite flagged)

**Observable:** artisan count per settlement at matched turns, seed 3, no orders, 650 turns, from
BOTH paths. **COMPOSITE? YES** — "the paths disagree" can mean the WORLDS differ or only the
REPORTING differs, and those are different findings with different severities. Both are read
separately: first the **world hash** per turn (identical worlds ⇒ any difference is reporting),
then the per-settlement counts.

**Branches, fixed now:**
- **The two paths AGREE and T4.1's control was misread** → a reporting error, filed against
  T4.1's record. **Small.**
- **The two paths DISAGREE on world state from the same seed** → **a DETERMINISM finding under law
  5. Report and STOP.** Do not continue into T4.1b's derivation.

## CANDIDATES TO CHECK FIRST, NAMED BEFORE LOOKING

1. **different founding entry point** — `WorldFounding.Found(wg, sim, seed)` (in-test) vs
   `HeadlessFounding.Found(seed, null, null)` (CLI); does the CLI pass a settlement COUNT the
   in-test overload defaults differently?
2. **different config** — already partially excluded: `TestConfigs.Worldgen()`/`Sim()` read the
   same `Sim.Data` streams the CLI does. Re-verify by comparing loaded values, not by reading the
   loader.
3. **different turn count / off-by-one** — the in-test probe recorded `t` from a 1-based loop; the
   reporter writes post-step state. A one-turn offset would shift emergence but NOT counts of
   121–665 vs 1.
4. **an in-test harness that skips a pipeline stage the CLI runs** — both claim
   `DataFiles.OpenPipeline()`, but the in-test probe built its executor by hand.
5. **a different CLASS ID** — the probe counted `Class.Value == 1`; the reporter matches on the
   registry NAME "Artisans". If class 1 is not Artisans, the probe measured a different class.

**Candidate 5 is the cheapest to check and would be a pure reporting error**, so it is checked
first — but the WORLD HASH comparison is run regardless, because it is the only reading that
separates the two branches cleanly.
