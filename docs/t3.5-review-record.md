## Mutation sweep (ADR-015 §7.1)

Bounds stated **before** the sweep: baseline 8.9 s / 52 tests; per-mutant bound 5× = 55 s; hard
timeout 120 s. **13 of 15 killed, every kill by a semantic test — no golden-only kills. No mutant
hung**, so there is no non-termination finding.

Survivors, both now closed with tests proven RED against the exact surviving mutant:

- **M3** — dropping weight normalisation in `Aggregate`. Left all 52 tests green. Not equivalent:
  shipped weights (1.0/0.9/0.3) with all needs at 0.5 give correct `S = 0.5` vs mutant `0.227`,
  roughly doubling grievance accrual everywhere. **Both** mandatory-acceptance rigs used weights
  `[0.5, 0.5]` — summing to exactly 1.0, where normalisation is a no-op — so they were
  *structurally* blind; the one rig with unnormalised weights asserted only upper bounds, which the
  mutant satisfies *more* comfortably than correct code (ADR-015 §7.5, one level up).
- **M8** — deleting the `!need.Bound` gate. Left all 52 tests green because the shipped basket set
  is exactly the bound set, so the next line reaches the answer first. Both inertness rigs were
  testing the no-basket path while their comments claimed they tested the `Bound` flag (§7.4
  exactly). The new rig gives an **unbound need a basket line**, so the flag is the only thing that
  can produce the asserted inertness.

## Open for director ruling — NOT acted on

1. **The all-farming default saturates Shelter and Comfort** — `docs/t3.5-shelter-saturation.md`.
   Independently corroborated by lens 5: peasant and artisan satisfactions are **bit-identical from
   turn 2** across 5 seeds × 300 turns, because the world produces one good and the class weights
   cancel exactly. The mechanism is right; the world has nothing for it to bite on.
2. **The variety reference point.** Normalising against perfect evenness means a perfectly supplied
   world scores 0.892, never 1.0, and the exact-saturation branch is **measured dead** in shipped
   config. The alternative (normalise to the declared basket) preserves your D-035-A rationale —
   verified: a grain-only settlement still takes the *full* penalty and still has reason to import
   fish — but widens self-certification, and the current form has the mirror-image flaw (declaring a
   good worth 0.1% of the diet permanently costs 0.004 satisfaction). **Neither reference point is
   principled.** Both `varietyWeight` and `expectation` are TUNE, so this needs no CR — but it is a
   design call, not mine to make.
3. **Ghost grievance for unemerged classes** — real, pre-existing, and now loud. Belongs to the
   T2.6/T2.13 line; fixing it re-pins goldens.
4. **Bound needs can still be silently inert** (lens 4, both confirmed): a basket naming a
   nonexistent class id loads clean, and a per-class hole in a bound need's basket is invisible
   because the guard is registry-scoped rather than (class, need)-scoped. Two load-time checks would
   close both; I have not added them because they change what configs are legal.
