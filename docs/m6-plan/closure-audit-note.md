# M6 closure — content/consequence audit and validation coverage (track AUDIT): decisions

**Status:** RECORD of routine decisions made under D-066 (§2 decision rules: simplest, deterministic, testable,
reversible), 2026-10-28. No contract, schema, simulation rule or golden is touched: the track changes validation tooling,
docs, content text outside both TC-1 hashes, and tests. Each item is reversible by reverting its file.

| # | Decision | Rationale |
|---|---|---|
| AU-1 | `scripts/research-gameplay-unlock-audit.py` reads goods.json `knowledge` on recipes AND on deposit/herd goods, and sim.json `discovery.assayRequires`, as class-B gates (new consumer types `recipe-knowledge`, `good-knowledge`, `assay`); rows of a disabled ADR-056 packet are skipped (removed at load). `--check` exits 1 on any §4 row typed `unlinked` or `unreachable` or resolved `OPEN`; writing never exits on them. | The seven EC recipes were false `unlinked` rows; `ore_prospecting` read as knowledge-only although DiscoverySystem enforces its gate. A defect-typed row is a defect, so the check must fail on it (it only checked staleness). The changes sit in new functions (`knowledge_gates`, `packet_enabled`, `blocking_rows`, `main`) plus two hook lines, to stay clear of the KNOW track's unit-families reading. |
| AU-2 | The closure-grade audit is a SIBLING script, `scripts/research-consequence-audit.py --check` → `docs/research-consequence-audit.md`, with rules R1–R10 (§1 of that file). | The unlock audit answers "which system realizes a node's content-declared consequence"; the consequence audit answers "is every item classified, and may any apply twice". Two questions, two files; neither script's output changes when the other's rules change. |
| AU-3 | The operand registry is MIRRORED in the script (operand → consuming system → consumed in play) and compared row for row with `Sim.Core/State/KnowledgeOperands.cs` on every run (R3). | The brief asks for a mirror; parsing the C# source as the check makes drift fail loudly instead of silently. |
| AU-4 | `unlocks.techniques` / `unlocks.applications` (33 + 7 free-text strings) are declared knowledge-only ONE BY ONE in `scripts/research-consequence-declarations.json`; an undeclared string is unclassified (R5 FAIL), and a declaration no longer in content is stale (R5 FAIL). `unlocks.capabilities` is knowledge text by list rule. | D-066 A5 (verb-granting knowledge is knowledge-only in M6). Per-string declaration gives the audit teeth for new free text; a list-wide rule would not. research.json is not edited (R3: trees accepted). |
| AU-5 | A deferred entity's owner and target come from the M7 building charter §9 register (`building.*`, `infra.*`, `project.*`, `inst.*`; kept complete by `check_charters.py`) and, for `unit.*` and the three deferred activities, from the declarations file. A declared owner for an entity that became realized is reported (§7), not failed. | D-066 A9 ("classified with an owning system and a target milestone, consistent with the M7 charters"); reporting rather than failing keeps a track that realizes an entity (the slice's law court) from breaking this audit at integration. |
| AU-6 | No-double-application rules DA-1..DA-6 (R8). The six levelled `frontier_*` repeatables that carry a completion delta AND a level effect on the same operand are RECORDED (§7, `docs/queue.md`), not failed. | ADR-047 applies the completion delta once; ADR-049 §1.6 adds the level benefit; both are summed before the registry cap. Two declared channels, not a duplicate within one. Whether level 1 should carry both is a content call for the Director; no content change (R3). |
| AU-7 | `validate.py --live` is the gate (corpus C01–C11 and Eureka V22 against the live research.json); the proposal-graph run is the historical snapshot, out of the gate, still runnable (`research-proposal-snapshot`, `where: manual`). `test_validate.py --live` runs the corpus fixtures (and two new live fixtures) with mutants. | D-066 A12.
