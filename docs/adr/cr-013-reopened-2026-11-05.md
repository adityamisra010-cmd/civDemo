## §3 Existing divergence: what is known

### 3.1 Measured cross-platform facts (DOC-ONLY here; MEASURED in the cited records)

1. **The Director's session against Linux** (CR:29–41, commit `98f25c1`, seed 42, canonical world, zero orders before
   turn 19):
   - hashes are equal at turns 0–1 and differ from turn 2 (`545ca00bd148…` on Windows, `28e62ffb26fb…` on Linux);
   - population, food and settlement count are equal at turns 0–5 (CR:45–47).
2. **Runner against runner** (CR §8.4–§8.5, run `34419607514`, commit `d8630e7`, SDK 10.0.401, RIDs `win-x64` and
   `linux-x64`):
   - turn 1: 40 blocks, 106,889 bytes, identical;
   - turn 2: first divergent field `PriceTerms[43].Consumption`, −2 ulp; `HarvestWeather` differs in 2 of 12 rows;
   - turn 3: `GoodStocks[154].ProduceRemainder`, 8,192 ulp;
   - every `long` column is equal on all three turns, and `CatchmentSummaries` is identical, which refutes CR-013 §2's
     first suspect;
   - the Windows runner's turn-2 hash equals the Director's own trace value, so CI reproduces his machine.
3. **Classification** (CR §8.6): "last-ulp transcendental divergence that has already propagated". The two tables that
   differ at turn 2 are exactly those fed by `Math.Exp`/`Math.Sqrt`/`Math.Log`/`Math.Cos` in `HarvestWeatherSystem` and
   `Math.Exp` in `PriceSystem`. By turn 3 the difference is banked in a remainder that decides a later integer floor.
4. **First standing surveillance run** (`docs/t4.19-verification-record.md:166–173`, run 34462298577 on `e08111b`):
   - Linux MATCH; Windows DIVERGED-AT-TURN-2;
   - at turn 3, `GoodStocks[154].ProduceRemainder` is 32,768 ulp apart, one `HarvestWeather` row differs, and every
     other table is byte-equal.
5. **A 161-turn played session** (`docs/t4.21-evidence/cascade-report.md:12`):
   - the Windows trace and the Linux trace agree at turns 0–1 and first differ at turn 2;
   - 42 of 609,554 telemetry leaves differ, in 39 turns: `economy.goods[].price` (33) and `social.grievance[].value` (9);
   - maximum relative difference 3.67e-16;
   - O17:64 adds that 0 of 1,932 settlement-turns differ in population.
6. **The Director's 68-turn win-x64 session** (D-058, cited at O17:65): "only divergence remains the ADR-022 platform one".

**The integer agreements above are samples, not a standard** (DIR5:354). CR-013 itself records that "has not yet" is not
"cannot" (CR:75). CR:352–356 notes that the first turn on which a `long` column differs has never been measured
beyond turn 5. Only seed 42, founded, 300 turns has ever been compared across operating systems (O17:66).

### 3.2 Root causes (from the O-17 prototype, `prototypes/m7-sprint1/Proto.DetMath`; Linux x64 only)

- **(a) MEASURED: the host libm is not correctly rounded** (O17:71–80). On 9,180 inputs checked against an independent
  arbitrary-precision oracle (Python `decimal`, 70–130 digits):

  | Function | glibc 2.39 correctly rounded | DetMath correctly rounded |
  |---|---|---|
  | exp | 2012 / 2013 | 2013 / 2013 |
  | log | 2508 / 2508 | 2508 / 2508 |
  | pow | 2946 / 2951 | 2951 / 2951 |
  | cos | 1707 / 1708 | 1708 / 1708 |

  In a sample of 2,939 DetMath/glibc disagreements, DetMath was correct in 2,939 and glibc wrong in 2,939.
- **(b) INFERRED, known .NET behaviour** (O17:82):
  - CoreCLR's `Math.Exp/Log/Pow/Cos` call the platform C runtime: the UCRT on Windows, glibc on Linux. Neither is
    correctly rounded, and they err differently in the last ulp.
  - Both libraries select code paths by CPU at run time, so a divergence between two machines on the **same** OS is
    possible. That has not been measured.
- **(c) Ruled out** (O17:84; CR §8.5):
  - `Math.Sqrt` (IEEE correctly rounded);
  - JSON and double parsing;
  - the RNG (integer PCG32; `RngStreams` equal at every compared turn);
  - FMA contraction (`Buckets` and `CatchmentNodes` are clean);
  - `(long)` casts;
  - worldgen and founding (turns 0–1 byte-identical).
- **Call sites** (O17:42–56; plan revision C11): `Math.Exp/Pow/Log/Cos` appear in 47 code lines, 48 calls in 15
  `Sim.Core` files (Exp 29, Pow 15, Log 3, Cos 1). The calls in `AutoplayMetrics`, `ResearchContent` and
  `UnitProgressionContent` are off the hash path.

### 3.3 The DetMath candidate (prototype, Linux only)

- **Method** (O17:31–37):
  - double-double kernels with exact argument reduction, built only from `+ − × ÷`, `Math.Sqrt` and bit casts;
  - no other `Math.*`, no FMA, no tables from outside;
  - its own source scan enforces this.
- **Accuracy** (O17:86–107): within 1 ulp of glibc on 10^6 inputs in each of 11 ranges, equal to it on 99.86–99.9998 %,
  0 mismatches on the 9,180 oracle vectors. It is not proven correctly rounded: the working precision is about 2^-100.
  It is deterministic, and equality needs only determinism.
- **Cost:**
  - 20–40× slower per call;
  - +8 % on the 300-turn founded run, measured on a loaded host, so it needs `sim bench` on a quiet host (O17:106, :123, :193).
- **Golden impact** (O17:109–151), measured in a private copy with all 48 calls replaced:
  - the final founded hash moves from `d5ebd0b2…` (= `FOUNDED_GOLDEN`) to `86fbbc16…`;
  - the first differing turn is 9 (`HarvestWeather[6].LogDeviation` +1 ulp);
  - no integer column differs at the sampled turns up to 300;
  - 16 of 78 determinism-filter tests move, all pinned world hashes, while every replay, twin and conservation harness
    and every AI semantic-turn pin holds;
  - INFERRED: every hash downstream of `HarvestWeather` moves;
  - this refutes the hypothesis that correctly rounded math would leave the Linux goldens unchanged (O17:153).
- **Verification status: not actionable until a verdict round.** The verifier's survivors and weak kills have had no
  reproduce-and-fix round (Phase B audit R13–R14; D-079 D19; `CLAUDE.md` / ADR-015 §6):
  - V1 is a scan gap: `double.Exp`, `double.Log` and friends are not banned by DetMath's source scan;
  - V2 survives, and whether it is an equivalent mutant has not been adjudicated;
  - V3–V5 are killed only by the oracle vectors;
  - the author mutant M7 (the `Ln2Lo` term) survives;
  - the author mutant M5 is a weak, oracle-only kill.
- **Windows: UNTESTED.** No DetMath test has run on Windows (O17:8–12).

### 3.4 What is not known

1. Whether `Proto.DetMath` is bit-identical on Windows. Its oracle vectors, identities and scan are platform-independent,
   so a green run on `windows-latest` would prove per-function equality for the tested inputs (O17:172).
2. The UCRT's correct-rounding rate. The test `HostLibm_AgainstCorrectlyRounded_IsRecorded` prints it once run on Windows.
3. The horizon at which a Windows/Linux `long` column first differs under today's libm (CR:352–356).
4. Seeds other than 42, the driven, first-reign, AI-world and toy goldens, and the recorded session fixtures, across
   operating systems.
5. Cross-machine divergence on one OS (the CPU-dispatch inference, §3.2 (b)).
6. The battle path: integer-only by construction in the prototypes (INV-1; DIR5:165), but never run on Windows.

## §5 When CR-013 closes again

CR-013 closes when Windows/Linux hash equality is **measured on both platforms**:
- exact equality of the full canonical stream, with no tolerance and no column subset;
- covering every per-turn hash of the founded golden (seed 42, 300 turns), the driven, first-reign, AI-world and toy
  goldens, at least the further seeds the X9 matrix fixes, and the battle-path goldens;
- including cross-platform replay of recorded sessions;
- with both legs blocking in CI on the development branch and on `main`.

No claim of equality is made before that ("Do not claim cross-platform hash equality unless it has actually been tested on
both platforms", carried at D-076 S82). Recording the closure is administrative. The Director is informed in the DIR5
§9 report.
