# T4.6 — FOREIGN TRADE: THE DECISION AND WHY IT IS THIS SMALL

**Director-ruled packet. Implemented against `main` `dfef2a2`. No schema change, no golden movement,
no new identity, no second economy.**

---

## 1. THE QUESTION, AND THE ANSWER

T4.6 asks for "the second polity's exchange; foreign-trade rules". The previous pass
(`t4.6-decision-inventory`) escalated it as **DIRECTOR DECISION REQUIRED**, on the grounds that
*"foreign" has no mechanical referent*. That escalation was correct when it was written and it is
still correct now — but the ruling resolves it: **foreign trade means trade across polity/control
boundaries, and nothing more is authorized.**

So the deliverable is a **classification**, not a mechanism:

```
trade between two settlements
        |
        +-- both answer to the same Empire   -> Domestic
        +-- they answer to different Empires -> Foreign
        +-- either answers to no Empire      -> Unruled
```

Everything the ruling forbids — tariffs, customs, treaties, sanctions, embargoes, guilds, money,
credit, treasury, transit loss — would have been a *mechanism*. None is implemented, and the
classification deliberately has no consumer inside the pipeline.

## 2. WHY NOTHING IS PERSISTED

`TradeFlowRow(From, To, Good, Quantity)` already carries both endpoints
(`Sim.Core/State/WorldState.cs:459`), and `ControlRow(Polity, Place, Strength)` already says who
rules a settlement (`:608`). **The scope of a trade is therefore a function of state that already
exists**, and computing it costs one scan of a table nothing else was going to scan.

Storing it instead would have:

- added a field to a serialized row, taking `CanonicalSchema` from v24 to v25;
- moved all four pinned world hashes, for a fact that is not simulation behaviour;
- created a second copy of a fact derived from `ControlRow`, free to disagree with it the moment
  control moves and something forgets to rewrite the flow.

The third is the real argument. A derived answer cannot go stale. `ScopeIsDerivedFromControl_…`
pins that property directly: control moves, the classification moves with it, and nothing is resynced.

**Consequence, stated because it is the packet's most useful outcome: T4.6 moves no golden and
changes no schema.** A test asserts the world hash is unchanged by the seam's presence.

## 3. WHAT WAS BUILT

| | |
| --- | --- |
| `EmpireQuery.TryGetController(world, place, out polity)` | the inverse of `ControlsSettlement` — who rules this settlement. Returns the FIRST control row, which is exact because D-037 A3 fixes control's cardinality at "exactly one, or none"; if a malformed world ever holds two, the earlier one is returned deterministically rather than by an unstable rule |
| `TradeScope { Unruled, Domestic, Foreign }` | the three answers |
| `TradeScopes.Classify(world, from, to)` | order-independent; the arbitrage pair loop visits each pair in an arbitrary orientation, so a scope that depended on orientation would be a defect |
| `TradeScopes.CountForeignFlows(world)` | a reader over this turn's realised flows |

No production system calls any of it. That is the same shape M4-B gave
`EmpireQuery.ControlsSettlement`: the question, published, with the policy left to the milestone that
owns it. M4-D later became that policy's first caller, which is the pattern working as intended.

## 4. THE FINDING: FOREIGN TRADE IS STRUCTURALLY UNREACHABLE TODAY

Measured from source, not inferred:

- **`WorldFounding` is the only producer of `Polities`, `Controls` and `Capitals` in the entire
  tree** (`Sim.Core/Worldgen/WorldFounding.cs:257,263,271`; the only other writes are the
  deserializer's). It creates **exactly one** Empire and gives it **every** founded settlement.
- **`ColonizationSystem` writes no control row at all.** A colonized settlement answers to nobody.

Therefore, in every canonical world: every pair of founded settlements is **Domestic**, every pair
involving a colony is **Unruled**, and **Foreign is unreachable — not rare, impossible.**

This is pinned by `FOREIGN_TRADE_IS_CURRENTLY_UNREACHABLE_IN_A_CANONICAL_WORLD`, deliberately named
to be impossible to misread. When something real creates a second Empire — secession, conquest, a
stateless colony taking control — that test fails and tells its reader the world has changed.

**Nothing was tuned, subsidised or forced to manufacture activity.** The packet forbids it, and it
would in any case have produced a number that measured the fabrication rather than the economy. The
related empirical fact stands unchanged and is not T4.6's to fix: canonical campaigns carry almost no
trade volume at all (`docs/m4-exit-inventory.md` §4 measured five units in a 650-turn campaign), which
is owned by the transport deadband escalation in `docs/queue.md`.

## 5. PRIOR WORK — THIS PACKET IS NOT THE FIRST ATTEMPT

Three earlier T4.6 branches exist and were read before anything was written here:

| branch | what it is |
| --- | --- |
| `t4.6-decision-inventory` | escalation: *"foreign" has no mechanical referent* |
| `t4.6-design-record` | a 370-line design record, design only |
| `t4.6-foreign-trade` | **an actual implementation** — the same predicate, placed inside `TradeArbitrageSystem` |

**The earlier implementation got one thing right that this one had wrong, and its rule was adopted.**
Its `TryGetController` resolves a malformed double-control by taking the **lowest `PolityId`**, making
the answer a function of the row SET rather than the row ORDER. My first draft returned the first
matching row, which is order-dependent: the same world serialized in a different order would name a
different controller — a law-5 determinism defect, not an inelegance.
`AMalformedDoubleControlResolvesByLowestPolityId_NotByRowOrder` now pins it.

**Where this differs, and why.** The earlier branch routes the classification through
`TradeArbitrageSystem`'s pair loop, replacing the existing `IsInfinity(pathCost)` guard with a
three-way kind. That is a defensible place — it is where M7 will attach — but it edits a certified
system to add a distinction nothing consumes. This packet keeps the classification as a pure reader
and leaves `TradeArbitrageSystem` byte-identical to `main`, which is the smaller production change
the ruling asks for. **The earlier branch remains available if the director prefers its placement.**

**One caveat on that branch, since it will be read after this:** its comments assert *"today EVERY
settlement is uncontrolled (nothing in the tree constructs a PolityId outside deserialization)"*.
That was true when written and is **false on `main` since M4-C** — founding now controls every
settlement. Its code is unaffected; its stated inertness proof is not.

## 6. THE MILESTONE-OWNERSHIP CONFLICT, RECORDED NOT RESOLVED

The M4 row asks for "foreign-trade **rules**". Two ratified documents place trade rules at **M7**:

- **D-037 C7** — *"RECOGNITION AS DIPLOMACY (M7)"* — makes recognition govern "legitimacy, **trade
  access** and the legitimacy cost of assertion" (`docs/d037-emergent-polities.md:119-121`).
- **D-040 B1** — *"Settlement, claim and trade all operate only within known extent"*
  (`docs/d040-discovery-and-control.md:39`), with extent placed at M7.

So a genuine T4.6 that shipped foreign-trade *rules* at M4 would implement M7's material early.
**This packet does not resolve that conflict; it avoids needing to.** It ships the boundary
*predicate* and no rule at all — no access gate, no friction, no coefficient — so nothing here
duplicates, pre-empts or contradicts C7 or B1. When M7 arrives, recognition and known-extent attach
to this classification instead of re-deriving it.

That is a deliberate narrowing of the M4 row, and it is the director's to accept or reject. If the
ruling intends actual rules at M4, it collides with C7 and B1 and needs a CR before implementation —
not a workaround. A third reason to hold: no border coefficient is derivable at M4 anyway, because
money is deferred (M4 ships no currency) and `ControlRow.Strength`, the one principled scaling
source, is computed by nothing.

## 7. WHAT THIS DOES NOT PREJUDGE

The classification is deliberately inert, so a later diplomacy or finance layer is free to decide
what a foreign trade *costs* or whether it is *permitted*. Nothing here presumes an answer: there is
no tariff hook, no treaty slot, no per-polity balance. A layer that wants one adds it against this
classification rather than around a stored flag.

The M3 transport ruling is untouched and was re-verified from source: transport cost enters as the
arbitrage **deadband** threshold (`TradeArbitrageSystem.cs:143`, `if (!(gap > threshold)) continue;`)
and never as a transit loss — no good is destroyed in transit anywhere in the system.
