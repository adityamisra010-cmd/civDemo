# T3.5 — coupling enumeration and the D-035-C carrier test

Required by `docs/t3.5-lens-manifest.md` lens 3 and by the handback checklist. D-035-C forbids
exactly one thing — `satisfaction_A` feeding into `satisfaction_B` with an invented weight — and
requires every real coupling to name a physical carrier: *a good, a purse, a building, a policy, a
body, a season.* A coupling that fits none of the seven paths has failed the test, not found an
eighth.

Below is **every** coupling T3.5 creates, with its path and its carrier. Nothing is omitted; the
last section lists the couplings that were considered and **refused**.

### On #3's path label, corrected

The original filing called staple substitution "path 1 — SHARED SATISFIER". That is wrong on
D-035-C's own definition: path 1 is one good serving *several **needs*** (its worked example is
cloth → Comfort *and* Shelter). Grain serves exactly one need and substitutes for another good
*within* it.

The right answer is that substitution is **not a coupling between satisfactions at all** — it is the
internal structure of a single satisfaction function, in the same way #8 is not a coupling. It
therefore needs no path, and the carrier test still passes on its own terms: the carrier is bread
eaten in place of fish. Claiming a path it does not fit was the error; D-035-C's rule that a
coupling fitting none of the seven "has failed the test, not found an eighth" applies to couplings
*between needs*, which this is not.

Note also that **no good in the shipped data serves two needs**, so path 1 has no instance anywhere
in T3.5. D-035-C instructs "Declare shared satisfiers in `needs.json`"; none are declared. That is a
defensible scope choice — cloth-as-bedding is exactly the kind of thing T3.8's housing stock should
carry — but it belongs in the refused list below rather than passing unmentioned, and it is now
there.

### On #8, which is the one that looks forbidden and is not

The Tier A gate reads `satisfaction(Sustenance)` and changes the **weight** of Comfort. It does not
change Comfort's *satisfaction*: a starving man's coat is exactly as warm as it was. What changes is
how much the coat matters to his grievance, and that is a statement about the aggregation, not a
transfer between needs. D-035-B named the gate explicitly and retained it unchanged, so it is
ratified rather than inferred — and if it were removed, no satisfaction value in the model would
change.

## Couplings considered and REFUSED

Recorded because a refusal is evidence and a silent omission is not.

- **"Poor Shelter raises the food requirement for warmth"** — this is a legitimate D-035-C path 3
  (DEMAND COUPLING, carrier: a body), and it is a real physiological effect. It is **not
  implemented** because implementing it needs a cold/exposure term that does not exist at M3;
  inventing one to justify the coupling would be fitting the world to the mechanism. Queued, not
  smuggled in.
- **"Comfort partially offsets Shelter"** — refused outright. This is the forbidden form: a
  satisfaction feeding a satisfaction with a coefficient, and no carrier exists for it. A blanket is
  a *good*, and if we want blankets to help, the way to do it is to put cloth in the Shelter basket
  (path 1, carrier: cloth), not to write `shelter += 0.2 × comfort`.
- **"Artisans are better fed because they are richer"** — refused as stated, because "richer" has
  no carrier at M3 (there is no purse yet). What ships instead is a *composition* difference at
  identical nutrition: the artisan basket eats the same person-year-equivalents, differently
  distributed. When M3.6/M3.7 give households a purse, the class difference gains its real carrier
  and this line can be revisited with one.
- **Path 1 shared satisfiers (e.g. cloth → Comfort *and* Shelter bedding)** — D-035-C's own worked
  example, and it is **not implemented**: no good in `needs.json` serves two needs. Declining the
  ruling's example is a scope choice, not an oversight — bedding belongs with the housing stock
  T3.8 builds, and adding it now would mean inventing a Shelter basket line whose only purpose is
  to instantiate a path. Recorded here because a completeness claim that silently omits the
  ruling's own example is not complete.
- **"A variety bonus for trading settlements"** — refused: that is law 2's free-floating buff. The
  variety term is inside the satisfaction equation and applies to everyone identically; a trading
  settlement benefits because it actually holds more different goods, which is a fact about its
  stores rather than a fact about it being a trading settlement.

## The forbidden form, searched for

`satisfaction_A → satisfaction_B` with an invented weight: **grep-level absent.** Satisfaction
values are produced in exactly one place (`NeedsGrievanceSystem.Satisfaction`), from basket lines and
published fill ratios only; they are consumed in exactly two (the `NeedSatisfactions` table, and the
`sat[]` span passed to `ApplyTierAGate`/`Aggregate`). No satisfaction is an input to another
satisfaction's computation anywhere in the packet.
