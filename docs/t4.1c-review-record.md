## THE DIAGNOSIS — VERIFIED, WITH ONE CORRECTION (§7.12)

Both names decomposed against the **shipped** pools:

```
Thiathiariath = th+ia | th+ia | r+ia+th   onsets [th, th, r]  nuclei [ia, ia, ia]
Naethaehun    = n+ae  | th+ae | h+u+n     onsets [n, th, h]   nuclei [ae, ae, u]
```

- **Naethaehun: exactly as reported** — nucleus `ae` twice.
- **Thiathiariath: the reported reading was "onset `thi` drawn twice". `thi` is not an onset** —
  the pool's onsets are single `th`. The real decomposition is **onset `th` twice AND nucleus `ia`
  THREE times**, so the dominant repeated element is the NUCLEUS, not the onset. **Both names are
  still repetition, so the fix shape holds**, but the detail differs and the tree wins.

## ITEM 1 — THE REFERENCE CLASS, FIXED BEFORE ANY OUTPUT WAS SEEN

**Class: Sumerian / Akkadian (third-millennium Mesopotamian) toponymy** — the era the opening
slice depicts. **Committed at `5d71acf`, before the constraints were written and before a single
generated name was looked at.** Commit order is the evidence (T3.5b / T3.2b discipline).

**Derived, not borrowed.** No real city name appears in the pools; placing Ur or Nineveh on a
procedural continent breaks the fiction and collides with cultural plurality at M8/M9.

**THE KEY PROPERTY, AND WHY IT FIXES THE PROBLEM AT SOURCE: Sumerian HAS NO DIPHTHONGS** — the
vowel inventory is `a e i u`. The old pools carried `ae`, `ia` and `ou`, which are exactly what
produced both bad names. Dropping them removes the vowel-cluster failure mode **structurally**
rather than filtering it afterwards — which is also the answer to the digraph question the packet
asked: **a digraph onset can no longer meet a digraph nucleus, because digraph nuclei no longer
exist.**

| pool | value |
| --- | --- |
| onsets | b d g k l m n p r s **sh** t z (13) |
| nuclei | a e i u (4) |
| codas | "" "" l m n r s t (8, two empty — the final-coda-only rule preserved) |

Recorded in `chronicle.json` beside the pools, with a note that **a second culture must be a
SIBLING pool keyed by culture id, never a widening of these arrays** — widening blends two
phonologies into an unpronounceable average, which is the failure this packet exists to fix.

## ITEM 2 — THE CONSTRAINTS

**Added:** no onset repeated within a name; no nucleus repeated within a name. Applied by
**bounded re-draw INSIDE the same splitmix64 stream** — `(seed, id, salt)` still determines the
name exactly. Never a filter carrying state across settlements. Re-draws are capped at 32 (never
`while(true)`), and on exhaustion the draw is taken as-is so `UniqueName`'s salt loop keeps the
failure loud at the right layer. Membership is a linear scan over 2–3 entries — arrays, not a
`HashSet`, per law 5.

**Positions stated, not added:**
- **Maximum rendered length: NOT added.** Measured max is **8 characters**, median 7. A cap would
  be inert today and would silently start rejecting if a future culture's pools were longer —
  a constraint that does nothing now and surprises later.
- **Digraph onset + digraph nucleus: NOT added, because it is now IMPOSSIBLE** — the reference
  class leaves no digraph nuclei. If a future culture reintroduces one, this is the rule to add
  with it.

## THE MEASURED SPACE — **AMPLE FOR THE CHARTER**

120,000 draws (200 seeds × 200 ids × 3 salts) yield **66,678 distinct names**. Length min 4,
median 7, max 8.

**Against the Scale Charter's late game of 300–800 settlements: 66,678 ≫ 800, by ~83×.** The
tighter constraints did not shrink the space into a problem. `UniqueName`'s 10,000-salt loop is
nowhere near exhaustion.

Longest cases, as a legibility check: `Shisuzan  Shapiden  Shubidas  Kishulen  Nishegat  Seshamim
Zushadem  Semushal` — all pronounceable, all 8 characters.
